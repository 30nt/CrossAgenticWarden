# Cross-Agentic Warden

*[English version](../README.md)*

Небольшой агентный пайплайн: он разбивает один запрос на задачи, реализует их по одной и даёт
отдельно настроенному reviewer судить каждую по доказательствам, которые та обязана была
произвести. Проект может требовать same-provider, different-model или cross-vendor review; CAW
проверяет фактическую пару вендоров и моделей до любого provider-вызова.

Роли явно привязаны к доверенным адаптерам провайдеров. Движок владеет протоколом, схемами,
гейтами, состоянием и коммитами — модели не владеют ничем из этого. Runtime состоит из Node-движка
без зависимостей и небольших вендоренных адаптеров провайдеров.

```
запрос ──▶ architect ──▶ plan-reviewer ──▶ спеки в .caw-tasks/
                ▲             │
           enumerator ────────┘   (что запрос подразумевал — сказано вслепую)

спека ──▶ executor ──▶ быстрый гейт ──▶ primary + challenger review ──▶ коммит
              ▲                                       │
              └──────── открытые пункты, по id ───────┘   (максимум 4 раунда, затем остановка)
```

## Правило, из которого следует остальное

> **Писать может только исполнитель, и только код.**

Не как совет — как флаг `--tools` у дочернего процесса каждого остального агента. [WHY.md](../WHY.md) —
измерение, которое породило это правило, и почему инструмент намеренно маленький.

## Что здесь действительно иначе

**Ревьюер не выносит вердикт.** Он заполняет слоты, вердикт выводит скрипт. Задача одобрена,
когда не осталось ни одного блокирующего пункта, и только тогда. Блокируют три слота, и каждый
пункт в них несёт `evidence` — что было запущено, изменено или процитировано на дереве перед
ревьюером:

| слот | значение | доказательство |
|---|---|---|
| `broken` | доставка делает не то, что заявляет | что было запущено |
| `uncovered` | строка `Must cover`, `Change` или `Done when`, которой дерево не удовлетворяет | что было проверено |
| `weak` | тест зелёный по неверной причине | **мутация, которая это доказывает** |

До этих слотов движок строит атомарный census из каждого пункта `## Must cover`, `## Change` и
`## Done when`. Ревьюер обязан вернуть disposition и evidence для каждого стабильного id;
пропущенные, повторные и неизвестные id делают ответ невалидным.

Открытый carried-пункт может подтверждать тот же non-met критерий без повторной регистрации.
Schema-valid, но семантически противоречивый ответ получает один вызов на исправление на неизменном
baseline ревью; повторное противоречие останавливает прогон.

По умолчанию primary и один слепой challenger-проход проверяют один и тот же digest доставки до
следующего запуска executor. Находки объединяются консервативно. Находка только challenger получает
метку `late-same-baseline`, а спор о старой находке оставляет её открытой.

Слабость, которую никто не продемонстрировал, — не `weak`. Четвёртый слот, `noted`, никогда не
блокирует и по нему ничего не происходит: он существует ровно затем, чтобы остальные три могли
оставаться строгими.

**Читайте пункты `noted`.** Они печатаются один раз в конце прогона и переносятся в коммит
задачи — это весь механизм; реестра нет и не будет. И именно туда попадает то, чего гейт дать не
может. На одном здешнем прогоне ревьюер удалил единственную строку, публикующую межскриптовый
канал, который рефакторинг только что сделал несущим, увидел, что гейт по-прежнему выходит с 0,
восстановил строку и записал это: гейт был зелёным и слепым, и сказал об этом только `noted`.

**Ревьюер обязан закрыть свои открытые пункты прежде, чем искать новые.** С раунда 2 ему выдают
их по id, и по каждому он обязан вернуть `closed`, `open` или `withdrawn` с указанием, что именно
он запустил для решения. Пропущенный id остаётся открытым: молчание ничего не закрывает. Без
этого ревьюер каждый раунд рисует список заново и не сходится — измерено на одном инсталле как
три пункта раунда 2, называющие тестовый код, которого не касалась ни одна правка раунда 1.

**Результат гейта никогда не проходит через агента.** Зелёный или красный — это код возврата.
Специалиста по запуску тестов удалили после измерения: 4 запуска, 256k токенов, 13% дорожки,
0 пригодных вердиктов.

Evidence задачи и очереди намеренно разделены. До task review ревьюер получает только
engine-owned receipt `gate_fast`. `gate_full` запускается один раз после review и commit всех
задач, поэтому это evidence завершения очереди, а не критерий приёмки отдельной задачи. Planning
roles получают этот lifecycle как контекст от движка. Специфичная для проекта проверка до review
входит в проектный fast gate; claims executor и proof-файлы не являются receipts.

Теперь результат gate имеет engine-owned receipt. Он связывает команду, status, длительность,
ограниченный output и digest проверенных артефактов с точным digest доставки. Проверки executor
хранятся отдельно как структурированные недоверенные claims. Reviewer видит оба набора в
ограниченном task dossier, а не получает по умолчанию всю накопленную историю; репозиторий
по-прежнему доступен для чтения.

Findings связаны со стабильными criterion, surface, transition и property. Точные root-cause keys
передаются executor как один work package, но исходное наблюдение каждого прохода и его provenance
остаются в истории. Сходство текста само по себе findings не объединяет.

Проект может включить [acceptance matrix API v3](project-policies.ru.md), не меняя ядро CAW.
Consumers, scenarios, observables, mutations, evidence kinds и selectors принадлежат проекту;
CAW проверяет полноту и транспорт gate evidence.

**Независимая population кэшируется только при полном смысловом совпадении.** В ключ входят
запрос, эффективный профиль и policy, canonical docs, состояние репозитория, project index,
runtime, адаптер, CLI, instructions, schema и движок. Любое изменение снова запускает enumerator.

**Гарантии берутся из живой пробы, а не из конфига.** Привязка недоступна, пока проба *на этой
машине* не докажет, что граница записи ОС держит. Изменение реализации адаптера, истёкшая
аттестация или красная проба делают её недоступной до вызова пайплайна.

## Требования

- **Node 18+** и `bash` в `PATH` (на Windows — Git Bash или WSL).
- **Граница файловой системы на уровне ОС.** macOS arm64: seatbelt через `/usr/bin/sandbox-exec`.
  Linux: `bubblewrap` (`apt install bubblewrap`). Ни то, ни другое не ставится за вас, и одно не
  заменяет другое. Хост без границы отказывает любой команде пайплайна.
- **CLI тех провайдеров, которых вы привязываете.** Claude резолвится как `CAW_CLAUDE` или
  `claude`; Codex — как `CAW_CODEX` или `codex`. Измеренный путь Codex для executor/reviewer —
  только macOS arm64, поэтому Linux-хост выполняет строки Claude и отказывает строкам Codex.
- **`python3`** для guard-хуков и **`pytest`**, чтобы проверить, что они подключены.

## Быстрый старт

```bash
git clone https://github.com/30nt/CrossAgenticWarden.git
cd CrossAgenticWarden
node --test test/*.test.mjs        # набор тестов движка, без трат
python3 -m pytest .caw/hooks       # набор guard-тестов, без трат
```

Затем в проекте, над которым он должен работать:

```bash
# 1. вендорим шесть путей — никогда не копируйте .caw/ рекурсивно
git -C <clone> -c core.autocrlf=false -c core.eol=lf archive --format=tar origin/main -- \
  caw.mjs .caw/agents .caw/adapters .caw/hooks .caw/CAW.md .caw/runtime.json | tar -xf -

# 2. заполняем профиль и привязываем все пять ролей
$EDITOR .caw/CAW.md          # как минимум: gate_fast
$EDITOR .caw/runtime.json    # провайдер + модель + reasoning, для каждой роли

# 3. доказываем границу на этой машине — этот шаг стоит денег
node caw.mjs probe claude

# 4. проверяем точные model/reasoning-привязки всех ролей — это тоже provider-вызовы
node caw.mjs smoke all

# 5. запускаем что-то маленькое и настоящее
mkdir -p .caw-logs
node caw.mjs plan "<something small>" > .caw-logs/plan.log 2>&1
```

[docs/install.md](install.md) — полная процедура, и она длинная намеренно: неверно подключённые
guard-хуки способны разом лишить сессию и `Bash`, и `Edit`.

## Команды

```bash
node caw.mjs plan "<request>"        # architect + reviewers → specs in .caw-tasks/
node caw.mjs build [--no-full]       # each spec: executor → fast gate → reviewer, until approved
node caw.mjs ship "<request>"        # both, without stopping to show you the plan
node caw.mjs review-specs "<request>"  # judge (and fix) whatever is in .caw-tasks/
node caw.mjs round <spec>            # one more review round on a task that stopped
node caw.mjs review <spec>           # review a task you finished by hand, and commit it
node caw.mjs done <spec>             # remove a spec with no review at all
node caw.mjs probe <provider>        # write current machine-local guarantee evidence
node caw.mjs smoke <role|all>        # verify exact model/reasoning role bindings
node caw.mjs human-review prepare plan <identity>
node caw.mjs human-review prepare task <spec> <identity>
node caw.mjs human-review accept <json> <sig>
node caw.mjs verify-project          # validate project policy extensions
node caw.mjs artifacts list          # retained run/recovery/probe/transport artifacts
```

Прогон, остановленный ролью, вернувшей невалидный канонический ответ, до коммита не доходит,
поэтому ничто из обычно сопровождающего задачу — ни публичный коммит со спекой дословно, ни
приватный аудит — не записывается. Такой отказ удерживается отдельно, в Git-пути
`caw/contract-failures/`: со спекой или запросом, отвергнутым значением, попытками починки и
точным runtime. Ротация, оставляющая двадцать новейших записей прогона, его не трогает.
`artifacts list` его показывает.

`ls .caw-tasks/` — это вся очередь. Публичное сообщение task-коммита остаётся коротким, а его
digest `CAW-Audit` указывает на полную приватную запись в Git-пути `caw/audit/`. Там после
удаления файла очереди остаются spec, notes, certification, identity policy, digest проверенной
доставки и staged tree. Каждая команда печатает разрешённую матрицу и digest runtime до любой
мутации и до любых трат.

Перед запуском дочернего процесса каждый provider-вызов создаёт неизменяемый `attempt-*.json`.
Run manifest связывает попытку, success, failure, timeout, interrupted-состояние, диагностику и
длительность одним `attempt_id`. Usage помечается как `reported`, `estimated`, `partial` или
`unknown`; неизвестное никогда не записывается нулём. Для неуспешного вызова создаётся только явно
помеченная оценка input по числу байтов, а не выдуманный reported usage. Перед автоматическим или явным удалением
старого run record CAW дописывает счётчики и длительности без payload в приватный Git-файл
`caw/metrics/runs.jsonl`.

## Прежде чем направлять это на настоящий репозиторий

- Он запускает написанный моделью код и **коммитит его**. Пока вы ему не доверяете — рабочая
  ветка в репозитории, который не жалко.
- **Граница записи — не граница чтения.** Любая роль с шеллом может читать вне дерева доставки и
  открывать сетевые соединения. [SECURITY.md](../SECURITY.md) описывает, насколько далеко это
  заходит; движок печатает сводку перед каждым платным вызовом.
- Автоматическое ревью остаётся ограниченной выборкой, а исполнитель всё ещё может сделать
  коммит через инструменты провайдера вопреки контракту движка. Эти и остальные риски, а также
  действующие контроли собраны в [docs/limitations.md](limitations.ru.md).
